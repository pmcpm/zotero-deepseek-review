# 写作模型调用与只读核查

## 生成动态提示词

提示词的结构固定，实质内容随任务变化：

1. 写作者身份、输出语种、章节类型和读者。
2. 任务题目、研究语境及作者实际提供的研究材料。
3. 章节论证结构、段落任务、研究路径比较维度、篇幅预算和引用组合。
4. 已核实证据卡、稳定 ID 及逐论点来源映射。
5. 字数口径与上限、引用格式、语言规范和内部自查要求。

正文使用 `[[R001]]` 类稳定 ID；相邻 ID 表示组合引用，最终顺序或作者年份交给 Zotero。正文之外的参考文献列表由 Word 插件生成。编号、研究发现、题录和研究结果均来自当前输入材料。

固定写作要求：按相关研究路径比较和综合，避免逐篇罗列；用直接、精确的学术陈述；所有连接符为 ASCII `-`；遵守用户的额外表达要求。默认检查“不表明”“不代表”“未使用”“不作为”“不能说明”“并不意味着”“不能证明”“需要强调”“值得注意”等防御性或冗余表达。必要的研究对象、条件和适用范围以具体正面表述保留。

提示词要求模型在返回前自行检查长度、证据、引用覆盖和表达。每一版保存完整可读 prompt 和实际 messages，请求中包含的证据版本与任务配置哈希一并记录。

## 模型调用和留档

按 [模型渠道](model-providers.md) 选择适配器。默认通过 `cstcloud-model-api` 的客户端与密钥管理调用 `deepseek-v4-flash`，沿用该 skill 的直连、超时、诊断规则。用户选择其他渠道时使用 OpenAI 兼容适配器与环境变量凭据。写作前查询实际模型列表；缺失时向用户报告可用选择。显式关闭模型发现的渠道须记录 discovery_skipped，由实际推理检查响应形状。

每轮独立目录保存请求、API 原始响应、抽取的 final content、用量、finish reason、模型参数、时间和正文 SHA256。正文抽取只读取 final content；内部推理保持私有，仅 final content 用于正文。模型返回内容保持原样，格式规整只作用于后续表示层。

成功响应后先检查终止状态和正文完整性，再做只读审查。已有完整结果时从保存的结果恢复；通用接口采用非流式请求，连接错误结果不确定时先检查供应商状态和已保存文件，再决定重试；完整响应后直接恢复，避免拼接两次不同生成。

## 审查与模型修正

机械核查：字数、章节、引用 ID 语法、未知与缺失 ID、需要覆盖的文献、非 ASCII 连接符、禁用表达及额外用户限制。Word 字数优先使用 Word 的实际统计；估算只能作为模型调用前后的预筛选，交付核查记录实际口径。统计剔除引文标识和文末参考文献，保留小节标题。

Codex 另做语义审查：每个具体论断对应来源，研究对象和方法范围准确，组合引用中的各篇支持相关内容，作者材料与文献综合有明确出处。脚本通过并不等于语义审查完成，将核对结论保存为单独记录。

`workflow.py write <task_dir>` 保存每轮结果并执行机械预筛选。机械预筛选通过后，运行 `word_count.ps1 -InputPath <本轮body.txt> -OutputPath <计数.json>` 取得 Word 字数；计数字段为 `{count, basis:"word", exact:true, body_sha256}`。Codex 语义审查保存为 `{body_sha256, passed, issues}`，其中 issues 提供具体位置、证据 ID 和问题。两份结果均绑定本轮正文哈希，再通过 `workflow.py review <task_dir> --semantic-review <file> --word-count <file>` 提交。审查对象变化时重新计数和核对。

发现正文问题时发送“原文 + 具体问题位置 + 对应证据 + 原任务约束”给本任务选定的写作模型修正。Codex 和子代理提供核查意见而不代写修改句。执行开场确认并记录的策略：`until_pass` 持续调用同一写作模型至验收通过，`max_revisions=null`；`bounded` 允许初稿加指定非负整数轮修订，未另设上限时为 2。每次响应独立留档，运输层重试与内容修订分别计数。

用户已授权持续修订时，不因达到两轮或其他固定轮数再次询问。未通过时汇总具体核查意见后继续；重复问题先复核证据、篇幅预算和提示词，再发起下一轮，不能改写原始模型正文。有限模式到达已确认上限时，保存原文和问题清单并报告该限制。证据缺失、服务故障、目标冲突及用户明确的调用预算是独立阻碍；说明实际原因并继续不依赖该阻碍的工作。存在未知 ID 或无法成立的引用映射时，先解决该问题再制作正式引文交付物。版本 1 旧任务没有执行策略时兼容有限 2 轮；会话的新授权按需求确认流程记录，供下一轮输入使用。

## 正文一致性

最后一次通过机械和语义审查的模型响应是正文来源。标题样式、段落、空白呈现和 `[[Rxxx]]` 到原生引文的转换属于格式处理。为每个正文段落保存来源位置与原生引文映射，正文哈希对应原始模型文本；交付检查在移除引用标识/引文结果并按同一空白规则规范化后比较正文。发现措辞差异时回到原始响应处理格式层，保持模型文字完整。

使用任务 `selected.json` 指向的已通过正文进行文档制作。调用 `workflow.load_selected(Path(task_directory))` 检查 `ready_for_word` 状态、输出许可、当前及不可变 task/evidence 快照、正文/raw/messages 哈希、题录读回、待补全文、精确计数及语义审查。模拟响应产生的结果仅用于隔离验证，正式交付重新调用实际模型并完成相同审查。改动任务或证据后重新生成写作响应并审查，避免把原文批准记录应用到不同证据包。
